# 토큰 예산 표준 (Token Budget Standard)

리서치 스킬이 **정확도를 낮추지 않으면서** 토큰을 태우지 않게 하는 공용 규칙.
`data-confidence.md`(정직성 표준)와 같은 층위의 공용 문서다 — 개별 스킬이 이 문서를 참조한다.

> ⚠️ 이 문서는 **정확도보다 우선하지 않는다.** 아래 상한에 걸려 데이터를 못 구했으면
> 추측으로 채우지 말고 `⬛`(데이터부족)으로 남긴다 —
> [data-confidence.md](skills/data-confidence.md) 핵심 원칙 4와 동일하다.
> "상한 때문에 빈칸"과 "상한 때문에 지어냄"은 완전히 다르다.

---

## 왜 필요한가 — 비용은 도구 호출 횟수의 **제곱**으로 는다

**소비 토큰 ≈ Σ(요청마다의 전체 컨텍스트 크기)**

도구 호출 1회 = 그때까지의 컨텍스트 전량을 다시 모델에 넣는 것이다. 웹검색 결과가 쌓이면
컨텍스트가 선형으로 커지고, 그 커진 컨텍스트를 매 호출마다 다시 낸다 → 총 소비는 제곱이다.

호출 40회 × 평균 컨텍스트 120k = **4.8M 토큰**. 에이전트 하나가 그렇다.

### 실측 (트랜스크립트 usage 집계, 2026-07-31 조사)

| 실행 | 서브에이전트 | 에이전트당 도구 호출 | 에이전트당 peak 컨텍스트 | 총 소비 |
|------|---|---|---|---|
| `/investment-team ADBE` (2026-07-24) | 4개 | 약 12회 | 52~72k | **5.9M** |
| `/investment-team QLYS` (2026-07-31) | 4개 | 40~60회 | 150~190k | **20.4M** |
| `/investment-team CEG` (2026-07-31) | **24개** | 40~60회 | 170~270k | **50.4M** |

CEG 39.5M(서브에이전트분) 중 **22.9M(58%)이 재시도로 버려진 분량**이었다. 실제 보고서를
만든 건 3차 웨이브 16.6M뿐이다. 게다가 2차 웨이브는 `You've hit your org's monthly spend
limit` 으로 죽었다 — **한도 초과 → 사망 → 재시도 → 추가 소비**의 악순환이 실제로 돌았다.

산출물 품질은 세 실행이 사실상 같았다. 즉 늘어난 토큰의 대부분은 **정확도가 아니라 낭비**였다.

## 하드 규칙 7가지

### TB-1. 서브에이전트는 또 다른 에이전트를 스폰하지 않는다 🔴

가장 비싼 사고다. CEG에서 서브에이전트들이 손자 에이전트를 10개 띄워 약 2.9M을 태웠고,
그 결과물은 부모의 컨텍스트로 다시 흘러들어 부모 컨텍스트까지 부풀렸다.

- 에이전트 팬아웃은 **팀 리드(본체)만** 한다. 깊이는 항상 1단계다.
- 서브에이전트 프롬프트에 이 금지를 **인라인으로 박는다** — 서브에이전트는 이 문서를 읽지 않는다.

### TB-2. 재시도는 총 1회까지

무응답 에이전트를 무한정 다시 띄우지 않는다.

- 1회 재시도해서 또 실패하면 **"제외하고 진행"을 기본값으로 자동 선택**한다(사용자에게 묻지 않는다).
- 빠진 관점은 보고서에 `⚠️ {역할명} 관점 누락 (Agent 무응답)`으로 명시하고 해당 차원은
  "데이터 부족"으로 표기한다 — 정직성 원칙 그대로다.
- 무응답 판정 전에 **반드시 산출물 파일부터 확인**한다: 에이전트가 파일은 다 쓰고 최종 보고
  메시지만 못 보낸 경우가 흔하다. 파일이 있으면 그걸 쓰고 재시도하지 않는다.

### TB-3. 에이전트당 조사 상한

| 도구 | 상한 (에이전트 1개 기준) |
|------|------|
| WebSearch | 10회 |
| WebFetch | 8회 |
| Bash | 10회 |

상한에 닿으면 **더 파지 말고 가진 자료로 즉시 보고서를 쓴다.** 못 구한 항목은 `⬛`.
7/24 기준선은 에이전트당 총 12회로 동일 품질을 냈다 — 40~60회는 수확 체감 구간이다.

### TB-4. 컨텍스트 120k 초과 시 조사 종료

컨텍스트가 120k를 넘으면 이후 호출 1회의 비용이 120k+다. 그 지점부터는 새 사실 하나를
얻는 비용이 보고서 하나를 쓰는 비용보다 비싸진다.

- 120k를 넘겼다고 판단되면 **추가 조사를 멈추고 즉시 작성 단계로 넘어간다.**

### TB-5. 파일은 Write 1회로 완결 — Edit 반복 금지

보고서 본문을 Edit로 21회 나눠 붙인 사례가 있었다. Edit 1회 = 컨텍스트 전량 재전송이다.

- 서브 보고서·최종 보고서는 **머릿속에서 완성한 뒤 Write 한 번**으로 저장한다.
- Edit는 저장 후 발견된 오류 수정에만 쓴다(수 회 이내).

### TB-6. 도구 호출은 묶는다

- 여러 셸 명령은 `&&`로 한 Bash 호출에 넣는다.
- `financial_rigor.py` 검증 여러 건은 **`batch` 서브커맨드로 한 번에** 실행한다:

  ```bash
  python3 tools/financial_rigor.py batch --spec '[
    {"cmd":"verify-market-cap","price":52.1,"shares":3.14e8,"reported":1.636e10,"currency":"USD"},
    {"cmd":"verify-valuation","price":52.1,"eps":6.43,"bvps":4.38},
    {"cmd":"cross-validate","field":"revenue","values":{"SEC":391,"Yahoo":390},"unit":"B"},
    {"cmd":"three-scenario","price":52.1,"eps":6.43,"shares":0.314,"growth":[0.15,0.08,0.0],"pe":[25,20,15]}
  ]'
  ```

  출력은 개별 실행과 동일하다(그대로 보고서에 붙이면 된다). 왕복만 4회 → 1회로 준다.
- 독립적인 조회는 **같은 메시지에서 병렬 호출**한다(순차 호출은 왕복 수를 그대로 늘린다).

### TB-7. 최근 산출물은 재사용한다 (중복 실행 금지)

CEG는 같은 날 `/investment-team`을 처음부터 두 번 돌려 65.5M을 썼다.

- 스킬 시작 시 `reports/{티커}/` 의 대상 산출물 **날짜부터 확인**한다.
- **7일 이내** 산출물이 있으면 전체 재실행하지 않는다. 사용자에게 알리고 선택하게 한다:
  ① 기존 보고서 갱신(변경된 부분만) · ② 특정 관점만 재실행 · ③ 전체 재실행(명시적 요청 시에만).

## 스킬 작성자를 위한 체크리스트

새 규칙을 스킬에 추가할 때 아래를 확인한다. 규칙 하나가 도구 왕복 하나를 만들면
그 스킬의 비용은 영구적으로 오른다.

- [ ] 이 규칙이 **새 도구 호출**을 만드는가? 기존 호출에 얹을 수 없는가?
- [ ] 여러 검증을 요구한다면 **한 번에 묶어 실행**하게 썼는가(TB-6)?
- [ ] 에이전트 프롬프트에 넣는 규칙인가? 그렇다면 TB-1·TB-3·TB-4·TB-5를 **인라인으로** 함께 박았는가?
- [ ] "반드시 검색할 것" 같은 무제한 지시를 넣었는가? → 상한과 함께 쓴다.
