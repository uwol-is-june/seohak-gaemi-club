# 산업 투자 리서치: 가치사슬 전체 스캔 + 병목 판정 + 4대 거장 종목 프로파일

$ARGUMENTS 산업에 대한 체계적인 가치사슬 투자 리서치를 수행한다.

## 리서치 목표

하나의 투자 테마/논리 체인에서 출발하여 다음을 완수한다:
1. 투자 논리 체인의 각 단계를 **양방향으로** 검증한다 (지지 + 반증)
2. 완전한 가치사슬 전체 지도를 그리고 **병목 섹터를 판정**한다
3. NYSE/NASDAQ/S&P500 전 상장기업을 스캔한다 (SEC SIC 스캔 포함 — 후속 퍼널이 재사용하는 마스터 풀)
4. 후보 종목(최대 8개)에 4대 거장 6차원 **프로파일**을 적용해 병목 판정을 역검증한다
5. **가치사슬 계층 수준**의 포트폴리오 배분 제안을 출력한다

> 🔗 **후속 스킬과의 경계** — 이 스킬은 "산업의 어디가 좋은가"에 답한다. "그 안에서 무엇을
> 얼마에 사는가"는 `/industry-funnel`(종목 정선) → `/investment-team`(종목 심층)이 답한다.
> 같은 종목을 같은 깊이로 두 번 분석하지 않는다.


- 대상 산출물(`reports/{섹터명}-industry-*.md`)이 **7일 이내**면 전체 재실행하지 않는다.
  사용자에게 **파일 날짜를 보여주고** 선택하게 한다([token-budget.md](skills/token-budget.md) TB-7):

  2. **부분 재실행** — 특정 단계만 (예: 3단계 스캔은 재사용, 4단계 프로파일만 갱신)
  3. **전체 재실행** — 사용자가 명시적으로 요청할 때만

- 90일 초과 또는 산출물 없음 → 전체 수행.

## ⓪-2 정량 데이터 수집 표준 (참조 — **여기서 실행하지 않는다**)

[financial-data.md](skills/financial-data.md) **0단계**가 이 스킬에도 적용된다: 웹 페이지를 긁기
전에 도구를 돌린다. 8종목 × 6지표를 손으로 긁으면 왕복이 수십 회로 불어나고 전사 오류가 섞인다.

🔴 **이 절은 규칙을 모아둔 곳이고, 실행 시점은 아래 표가 정한다.** 티커가 확정되기 전(1~2단계)에
`fetch_financials.py`를 돌릴 수는 없으므로 순서를 표로 고정한다:

| 실행 시점 | 무엇을 | 대상 | 상한 |
|---|---|---|---|
| **2.2 표 작성 전** | 스크리너 1회로 섹터 대표 ROIC 일괄 수집 | 섹터당 대표 2~3개 | **섹터당 조회 1회** |
| **4.0-a 작성 전** (3단계 스캔 후, 대상 8종목 확정 후) | `fetch_financials.py` | 프로파일 대상 티커만 | 티커당 1회 |
| **4.N E 차원 작성 전** | `financial_rigor.py batch` | 같은 8종목 묶어서 | **batch 1회** |

### 1) 연간 재무 — `fetch_financials.py` (4.0-a 직전)

```bash
python3 tools/fetch_financials.py {티커} --years 10 --cross
```

- 산출 `reports/{티커}/_data.md` — SEC EDGAR XBRL 원문 직독이라 **🟢[사실]** 등급이다.
  (`_` 접두어라 대시보드 보고서 목록에서 자동 제외된다 — 화면을 오염시키지 않는다.)
- 4.0-a 정량표의 **FCF 마진 · 순부채(현금성자산 − 총부채) · Gross Margin · ROE**가 여기서 나온다.
- 이 도구가 **주지 않는 것**: 주가·PER·PBR·EV/EBITDA·ROIC → stockanalysis.com에서 보충한다.

### 2) 파생 지표·검산 — `financial_rigor.py` (E 차원 직전)

**손계산하지 않는다** (CLAUDE.md 주의사항). 8종목을 **batch 하나로** 묶는다(TB-6 — 왕복 8회 → 1회):

```bash
python3 tools/financial_rigor.py batch --spec '[
  {"cmd":"verify-market-cap","price":52.1,"shares":3.14e8,"reported":1.636e10,"currency":"USD"},
  {"cmd":"verify-valuation","price":52.1,"eps":6.43,"bvps":4.38},
  {"cmd":"three-scenario","price":52.1,"eps":6.43,"shares":0.314,"growth":[0.15,0.08,0.0],"pe":[25,20,15]}
]'
```

- **시가총액은 반드시 검산한다** — 주가 × 발행주식수를 `verify-market-cap`으로 대조한다
  (3단계 스캔 표와 4.0-a 정량표의 시총).
- **4단계 E의 "안전마진 %"는 `three-scenario` 출력이 근거다.** 근거 없이 감으로 % 를 쓰거나,
  도구를 돌리지 않은 채 매번 "산정 불가"로 남기는 것 둘 다 이 절 위반이다.

## 1단계: 투자 논리 체인 구축 및 검증

### 1.1 논리 체인 그리기
"근본 트렌드"에서 "수혜 종목"까지의 인과관계를 화살표 흐름으로 표현한다. 예시:
```
근본 트렌드 A
    → 수요 B를 창출
        → 병목/필수 수요 C를 만든다
            → 수혜 가치사슬 D
```

예시 (반도체 섹터):
```
AI 모델 파라미터 확장 경쟁
    → 고성능 GPU/HBM 수요 급증
        → 첨단 패키징·HBM 공정이 병목
            → NVDA, TSMC, SK Hynix, Micron 수혜
```

### 1.2 각 단계별 검증 (양방향)

화살표 하나 = 가정 하나다. **지지 근거만 모으면 검증이 아니라 확증 편향이다** — 각 화살표마다
"이 가정이 틀렸다면 무엇이 관측될까"를 먼저 적고, 그 관측이 실제로 있는지 찾는다.

| 단계 | 핵심 가정 | 지지 근거 | **반증 시도** — 틀렸다면 무엇이 보일까 | 데이터 출처 |
|------|----------|----------|--------------------------------|-----------|
| A→B | | | 수요가 안 늘거나 다른 곳으로 갔다는 신호 | SEC 10-K(Item 1 Business·Item 7 MD&A), 산업협회·시장조사 보고서 |
| B→C | | | 병목이 다른 곳이거나 이미 해소됐다는 신호 | SEC 10-K(Supply/Risk Factors), 기업 IR, cnbc.com |
| C→D | | | 수혜가 다른 계층으로 갔다는 신호 (마진이 고객사·경쟁사로 이전) | SEC 8-K, seekingalpha.com(WebSearch 경유) |

> ⛔ **반증 열이 빈 채로 2단계로 넘어가지 않는다.** 비어 있으면 검증이 끝난 것이 아니라
> 시작하지 않은 것이다. 화살표가 3개보다 많으면 행을 늘린다 — A→B/B→C/C→D는 예시일 뿐이다.
>
> **가장 약한 고리를 명시한다**: 세 화살표 중 반증 근거가 가장 많거나 지지 근거가 가장 얇은
> 마디를 지목한다. 이 고리가 1.4 체인 전체 판정의 입력이 되고, 거기서 나온 확신도가
> 5.1·7.1·8단계로 흘러간다 (사슬의 강도는 가장 약한 고리가 정한다).

### 1.3 "이미 발생한 검증 이벤트" 찾기 (양방향)

**예측이 아니라 이미 체결·실행된 실제 비즈니스 이벤트**만 센다. 애널리스트 전망·목표주가·
시장 규모 추정치는 여기 들어올 수 없다(그건 5~6단계에서 다룬다).

| 방향 | 찾을 것 | 예시 |
|------|--------|------|
| **지지** | 체인을 뒷받침하는 실제 사건 | 장기 공급계약 체결, 대규모 Capex 집행 공시, 주요 고객사의 채택 발표, 8-K 실적 서프라이즈 |
| **반증** | 체인과 어긋나는 실제 사건 | 계약 취소·축소, 가이던스 하향, 대체 기술 채택 사례, 병목 해소 신호(증설 완료·리드타임 단축), 핵심 고객 이탈 |

> ⛔ **반증 이벤트가 0건이면 "없다"가 아니라 "충분히 찾지 않았다"로 간주한다.**
> 반증 이벤트를 명시적으로 검색한 뒤(키워드에 cancel, delay, downgrade, oversupply,
> capacity expansion, alternative 등 포함) 그래도 0건이면 **"반증 검색 수행함 — 해당 없음"**
> 이라고 명시한다. 검색하지 않은 것과 검색해도 없는 것은 다르다.
>
> (근거: CLAUDE.md 투자 분석 핵심 원칙 "양면 제시" — 모든 핵심 판단에 반대 근거를 첨부한다.
> **논리 반증은 여기서 한다** — 5.3에서 하기엔 체인이 이미 굳은 뒤라 늦다. 5.3은 논리가 아니라
> 가격 심리(앵커링·군중)를 점검하는 다른 층이므로 뒤에 있는 것이 맞다.)

### 1.4 체인 전체 판정 ⚑

1.2(가정별 검증)와 1.3(실제 이벤트)을 **하나의 판정으로 수렴**시킨다. 이 판정이 5.1·7.1·8단계로
흘러가므로, 여기서 결론을 내지 않으면 뒤의 세 곳이 각자 다른 확신도를 쓰게 된다.

| 항목 | 기록 |
|------|------|
| **가장 약한 고리** | (화살표 하나를 지목 — 예: `B→C`) |
| 그 고리가 약한 이유 | 지지 근거가 얇은가 / 반증 이벤트가 실제로 나왔는가 |
| **체인 전체 확신도** | 높음 / 보통 / 낮음 — **가장 약한 고리 기준** (사슬은 최약 고리가 강도를 정한다) |
| 이 판정을 뒤집을 관측 | 앞으로 무엇이 관측되면 확신도가 한 단계 오르내리는가 |

> ⚑ **이 판정은 그대로 세 곳에 복사된다**: 5.1 리스크 표 첫 행 · 7.1 테마 비중 상한 · 8단계 종합
> 평가표 "투자 논리 체인" 행. 세 곳의 값이 서로 다르면 보고서가 자기모순이다.
>
> ⛔ 확신도가 **낮음**인데 7단계에서 코어 포지션을 제안하지 않는다. 낮음이면 7.1 상한을
> 한 자릿수 %로 내리거나 "관찰만" 결론이 정직하다.

## 2단계: 가치사슬 전체 지도 그리기

### 2.1 가치사슬 구조 그리기
산업을 업스트림 → 미드스트림 → 다운스트림 → 보조 섹터로 분해한다. 예시:
```
업스트림:   원자재/자원 채굴 → 소재 가공/정제
미드스트림: 핵심 장비 제조 → 시스템 통합/엔지니어링 → 신기술 R&D
다운스트림: 운영/서비스 → 최종 고객
보조:       테스트/인증 → 유지보수 서비스 → 금융 수단 (ETF/REITs)
```

미국 주요 섹터별 가치사슬 예시:
- **반도체**: EDA 소프트웨어(Synopsys/Cadence) → 웨이퍼 장비(AMAT/LRCX/KLAC) → 파운드리(TSMC/Intl Foundry) → 팹리스 설계(NVDA/AMD/QCOM) → 최종 시스템 통합
- **핀테크/결제**: 네트워크 인프라(Visa/Mastercard) → 결제 처리(FIS/Fiserv) → 소비자 앱(PayPal/Block) → 임베디드 금융(Stripe 등 비상장)
- **클라우드/AI 인프라**: 데이터센터 하드웨어(NVDA/AMD) → 하이퍼스케일러(AMZN/MSFT/GOOGL) → 플랫폼 서비스(Snowflake/Databricks) → AI 앱 레이어
- **헬스케어**: 제약 원료(specialty chem) → 임상 CRO(IQVIA/Medpace) → 대형 제약(JNJ/LLY/PFE) → 의료보험(UNH/CVS) → 의료 IT(Epic 등)
- **에너지 전환**: 원자재 채굴(리튬/희토류) → 배터리 셀(Panasonic/CATL 비상장) → EV OEM(TSLA/GM/F) → 충전 인프라(CHPT/EVGO) → 유틸리티(NEE/AES)

### 2.2 각 섹터의 "비즈니스 특성" 파악
각 섹터에 다음을 표시한다:

| 섹터 | 비즈니스 모델 | Gross Margin 범위 | **실측 ROIC** | 경쟁 구도 | 해자 유형 | 경기 민감도 |
|------|-------------|-----------------|--------------|----------|----------|-----------|
| | 자원판매/장비판매/서비스/구독 | | 대표 기업 2~3개 중위값 | 독점/과점/완전경쟁 | 자원/라이선스/기술/규모 | 강/중/약 |

> 🔴 **ROIC 열이 2.3 병목 판정의 실질 근거다** — 빈칸으로 두면 병목 판정이 정성적 인상에 의존한다.
> Gross Margin은 회계 구조(원가 계상 범위·감가상각 배분)가 섹터마다 달라 **섹터 간 비교에
> 부적합**하다. 자본 효율을 직접 재는 ROIC가 "이 계층이 초과수익을 가져가는가"에 답한다.
>
> - 출처: `stockanalysis.com/stocks/{ticker}/financials/ratios` (ROIC 행)
> - 섹터 대표 기업 2~3개의 ROIC를 뽑아 **중위값**을 쓴다(평균은 이상치에 끌린다).
> - 섹터에 상장사가 1개뿐이면 그 값을 쓰고 "표본 1개"라고 병기한다.

> 🔴 **조회 예산과 순서** — 이 표는 3단계 스캔보다 **앞에** 있지만 기업 목록은 3단계가 만든다.
> 순서를 그대로 두고 아래로 비용을 막는다(2.3 병목 판정 없이는 3단계 Tier 분류의 우선순위가
> 정해지지 않으므로 절을 뒤로 옮기지는 않는다):
>
> - 여기서 쓰는 대표 기업은 **사전 지식으로 지목한 2~3개**다(2.1 가치사슬 예시의 기업들).
>   전 상장사를 뒤져 고르는 작업이 아니다 — 그건 3단계의 일이다.
> - **섹터당 조회 1회 상한**: 대표 2~3개의 ROIC는 **stockanalysis.com 스크리너**에서
>   **한 페이지로 묶어 받는다**. 종목당 개별 페이지를 열지 않는다
>   (6섹터 × 3종목 = 18회 조회가 되고, 이 비용은 3단계 팬아웃 상한에 계상돼 있지 않다).
> - ⚠️ **finviz 스크리너로 ROIC를 대체하지 않는다** — finviz 무료 컬럼은 ROA·ROE·**ROI**이고
>   ROI는 ROIC와 정의가 다르다. 그걸 옮겨 적으면 이 표가 **다른 지표를 ROIC라고 표기**한다.
>   ROIC 컬럼이 없으면 값을 만들지 말고 `⬛`로 두거나, 그 지표가 ROI임을 명시한다.
> - ⛔ **4.0-a와 겹치는 티커는 재조회하지 않는다.** 여기서 뽑은 ROIC를 4.0-a에 그대로 옮겨 쓰고,
>   4.0-a는 **여기 없는 티커만** 새로 조회한다.

### 2.3 "병목 섹터" 판정 ⚑

가치사슬에서 공급이 가장 타이트하고, 대체가 가장 어려우며, 마진이 가장 높은 섹터를 식별한다.
이런 섹터가 최적 투자 종목이 있는 곳이다.

**통념과 대조한다** — 시장이 "이 산업의 병목"이라고 부르는 곳과 2.2 표의 실측 마진·ROIC가
가리키는 곳이 같은가? 다르면 그 불일치 자체가 이 보고서의 핵심 발견이다.

| 항목 | 기록 |
|------|------|
| 시장 통념상의 병목 | |
| **실측이 가리키는 병목** (2.2의 마진·ROIC 근거) | |
| 일치 / 불일치 | 불일치면 그 이유 |
| **4단계 역검증 결과** ← 4단계 완료 후 되돌아와 채운다 | 지지 / **반증** — 반증이면 아래 규칙 적용 |

> ⚑ 이 판정이 **4단계 종목 선정의 우선순위를 정한다** — 병목 섹터의 선두 기업부터 분석한다.
>
> 🔴 **역검증 루프를 닫는다** — 4단계의 목적 ①이 이 판정의 검증이다. 4단계에서 병목 섹터
> 선두 기업이 **다른 섹터 선두보다 ROIC·해자·안전마진이 열등하게** 나오면 그건 "의외의 결과"가
> 아니라 **이 판정이 틀렸다는 증거**다. 그때는:
>
> 1. 이 표의 마지막 행에 **반증**으로 적고, 무엇이 어긋났는지 한 줄로 쓴다.
> 2. **위 '실측이 가리키는 병목'을 수정한다** — 4.0-a 정량표가 실제로 가리키는 섹터로 고친다.
> 3. 그 변경을 **8단계 '최적 섹터' 행과 7.2 배분에 반영**한다. 2.3을 고치지 않고 4단계 결과만
>    그대로 두면 보고서가 자기모순이다(8단계는 2.3을 그대로 받아 적는 자리다).
>
> ⛔ 판정을 수정했으면 **수정 전 판정도 남긴다**(취소선 또는 "초기 판정: X → 수정: Y"). 통념과
> 실측이 갈린 지점이 이 보고서의 핵심 발견이므로, 조용히 고치면 그 발견이 사라진다.

### 2.4 상장 수단이 없는 핵심 플레이어 (상장 기업 편향 교정)

가치사슬에서 **가장 중요한 플레이어가 상장돼 있지 않은 경우**를 명시적으로 적는다. 이걸 빠뜨리면
"상장된 것 중 최선"을 "이 산업의 최선"으로 착각하게 된다(2.5 편향 표의 '상장 기업 편향').

| 플레이어 | 가치사슬 위치 | 비상장 형태 | 투자 접근 가능성 |
|---------|-------------|-----------|---------------|
| | | 비상장/국영/사업부/외국 비상장 | IPO 후보 / 모회사 우회 / **접근 불가** |

- **접근 불가**로 판정되면 그렇게 쓴다. 억지로 "대리 종목(proxy)"을 만들지 않는다 —
  대리 종목은 대개 해당 산업 매출 비중이 낮아 논리 체인과 무관하게 움직인다.

### 2.5 AI 리서치 편향 자각 — 산업 리서치의 특수 함정

> 🔴 **3단계 스캔 직전에 읽는다.** 아래 편향은 스캔·선별 단계에서 발생하므로, 5.3 편향 점검처럼
> 뒤에서 읽으면 이미 후보군이 굳어 손댈 수 없다. 이 절은 **개입 가능한 시점**에 놓여 있다.

산업 리서치에서 AI 데이터 편향은 특유의 방식으로 증폭된다:

**산업 수준 편향**:
| 편향 유형 | 나타나는 방식 | 대응 방법 |
|----------|------------|---------|
| 성숙 산업 선호 | 전통 산업(은행/에너지/소비재) 자료가 방대해 AI 분석이 "더 확실해" 보임 | 확실성은 비즈니스 모델에서 오는 것, 리서치 보고서 수에서 오지 않음 |
| 신흥 산업 과소평가 | 신산업(AI 앱/합성생물학 등) 자료가 적어 AI 분석이 보수적으로 편향 | "현재 데이터"가 아닌 "최종 상태(endgame)" 사고로 산업 가치를 판단 |
| 대형주 선호 | 대기업 자료가 소기업보다 훨씬 많아 AI가 자연스럽게 대형주를 추천 | 소형주가 더 나은 위험/수익 비율을 제공할 수 있음. AI 분석이 짧다고 무시하지 말 것 |
| 상장 기업 편향 | 상장기업만 스캔하면 가치사슬의 핵심 비상장 플레이어를 놓침 | 비상장 기업 반드시 검색, "미래 IPO 후보"로 표시 |
| 영문 자료 편향 | AI가 영문 자료를 더 잘 처리해 아시아/유럽 경쟁자를 과소평가할 수 있음 | 외국 경쟁자의 SEC 공시(20-F)와 영문 자료를 별도 검색 |

**가치사슬 스캔의 반편향 조치**:
1. 각 섹터에서 "AI가 쉽게 찾는 기업"뿐 아니라 "비주류지만 잠재적으로 우수한 종목"을 능동적으로 검색한다
2. 정보가 부족한 소형주라도 분석 분량이 짧다는 이유로 추천도를 낮추지 않는다. 핵심 질문(비즈니스 본질, 해자, 경영진)으로 판단한다
3. 최종 보고서에서 각 기업의 "정보 충분도"(A/B/C 등급)를 표시해 독자가 AI 분석의 신뢰도를 파악하게 한다
   (등급 정의는 4단계 앞에 있다)

## 3단계: 전체 상장기업 스캔 (마스터 스캔)

Task 도구를 사용해 백그라운드 Agent를 실행하고, 해당 산업의 모든 상장기업을 포괄적으로 검색한다.

> 🔗 **이 스캔이 해당 섹터의 마스터 후보 풀이다.** 후속 `/industry-funnel` 1단계는 이 결과를
> 재사용하며 전체 시장을 다시 스캔하지 않는다([industry-funnel.md](skills/industry-funnel.md) ⓪-2 참조).
> 따라서 여기서 누락하면 퍼널에서도 영영 복구되지 않는다 — 아래 SIC 스캔을 반드시 수행한다.

> **팬아웃 상한 ([token-budget.md](skills/token-budget.md))** — 이 단계는 Agent 수 지정이 없어
> 실측에서 서브에이전트가 31~41개까지 늘어난 적이 있다(2026-07-27 AI Infrastructure 15.7M,
> 07-28 E-commerce 25.3M). 아래를 지킨다:
>
> - **SIC 전체 스캔은 본체가 먼저 1회 수행한다** (아래 절). 산업 단위 작업이라 섹터 Agent에
>   맡기면 6개 Agent가 같은 조회를 6번 한다. 결과 목록을 각 Agent 프롬프트에 넣어 넘긴다.
> - **Agent는 가치사슬 섹터별로 1개씩, 최대 6개**. 기업 1개당 Agent를 띄우지 않는다
>   (이 단계는 목록·분류 작업이지 심층 분석이 아니다).
> - 🔴 **Agent는 하위 Agent를 스폰하지 않는다** (TB-1). 팬아웃은 본체만, 깊이는 1단계.
>   이 금지를 각 Agent 프롬프트에 **인라인으로** 박는다.
> - **Agent 1개당 조사 상한**: WebSearch 10회 · WebFetch 8회. 결과는 **Write 1회**로 낸다.
> - 재시도는 Agent당 1회까지. 실패하면 그 섹터는 "데이터 부족"으로 표기하고 진행한다(TB-2).
> - ⚠️ 이 스킬 1회 실행의 정상 범위는 **5~12M 토큰**이다(2026-08-06 이전 실측 — 4단계 8종목
>   상한 도입 전 기준이므로 현재는 더 낮게 나오는 것이 정상이다). **12M을 넘고 있으면 멈추고
>   원인을 본다** — 재시도 루프·손자 에이전트·전체 시장 재스캔 중 하나다.

### 🔴 SEC EDGAR SIC 코드 전체 스캔 (누락 방지의 핵심)

finviz 무료 계정은 세부 필터가 제한돼 **거래대금·시총 상위에 없는 중소형 니치 종목이 처음부터
누락**된다. 스크리너만 쓰면 대형주 편향이 스캔 단계에서 이미 구조적으로 박힌다.

```
sec.gov/cgi-bin/browse-edgar?action=getcompany&SIC={코드}&type=10-K&dateb=&owner=include&count=300
```

- EDGAR는 거래대금·시총으로 거르지 않고 **해당 SIC에 등록된 전 상장사**를 보여준다.
- SIC 코드를 모르면 WebSearch로 `"{산업명} SIC code"` 또는 대표 기업의 EDGAR 프로필에서 확인한다.
- ⚠️ 다수 외국 발행사(ADR)는 10-K가 아닌 **20-F**를 제출한다 → `type=20-F`로 **한 번 더** 조회한다.
- 그래도 남는 누락 가능성은 부록 A(데이터 부족 항목)에 기재한다.

보조 교차 스캔: stockanalysis.com 스크리너(다른 필터 기준) · 섹터 ETF 상위 보유 종목 ·
SEC 13F(저명 가치투자 펀드 보유 종목을 후보군에 강제 편입)

- 기업명 및 티커

- 시가총액 (대략적 규모)
- 한 문장 설명 (가치사슬에서의 위치와 역할)
- 순수 플레이 여부 (예: 순수 반도체 vs 반도체 사업부 포함 대형 복합기업)
- 가치사슬 소속 섹터

### 출력 형식
가치사슬 섹터별로 분류하고 각 섹터에 표를 작성한다.
이후 투자 확실성에 따라 계층화한다:
- **Tier 1**: 대형주, 순수 플레이, 섹터 선두주자
- **Tier 2**: 중형주, 순수 또는 높은 비중, 세부 섹터 선두
- **Tier 3**: 소형주, 개발 단계, 고위험 고탄성
- **Tier 4**: 관련 사업부가 있는 대형 복합 기업

## 4단계: 후보 종목 프로파일 — 4대 거장 6차원

### 🔴 이 단계의 목적과 한계 (먼저 읽는다)

**목적은 매수 판단이 아니라 ① 2.3 병목 판정의 검증과 ② 후보 압축이다.**
"병목 섹터의 선두 기업이 실제로 우월한 재무·해자를 갖는가"를 확인해, 병목 판정이 맞았는지
역으로 검증한다.

🔴 **검증 결과는 반드시 2.3 표의 '4단계 역검증 결과' 행에 기록한다.** 병목 섹터 선두가
평범하거나 다른 섹터 선두에 밀리면 "의외의 결과"가 아니라 **2.3이 틀렸다는 증거**이므로,
2.3으로 돌아가 판정을 수정하고 그 변경을 7.2·8단계에 반영한다(2.3 ⚑ 규칙 참조).
"의심한다"로 끝내고 넘어가면 검증 루프가 열린 채 보고서가 나간다.

| | 이 스킬(research) 4단계 | `/industry-funnel` 4단계 |
|---|---|---|
| 대상 | 후보 **최대 8종목** | 최종 **3종목** |
| 깊이 | 차원당 3~6줄 (**프로파일**) | 종목당 800~1200자 (**심층**) |
| 산출 | 후보 압축 + 병목 검증 | 매수 판단·비중·매매 신호 |

> ⛔ **같은 종목을 같은 깊이로 두 번 분석하지 않는다.** 심층 4대가 분석은 퍼널이 담당한다.
> 여기서 800자짜리 종목 서술을 쓰고 있다면 스코프를 넘은 것이다.

### 정보 충분도 등급 (아래 모든 종목 블록 제목에 표기)

투자 판단이 아니라 **분석 자체의 신뢰도 라벨**이다. 2.5 "가치사슬 스캔의 반편향 조치 3번"에서 온다.

| 등급 | 기준 |
|-----|-----|
| **A** | `_data.md`(SEC XBRL 직독)로 10년 재무 확보 **+** 10-K 원문 확인 **+** 독립 계보의 2차 출처(Yahoo·CNBC 직접 접근) |
| **B** | 주요 재무 데이터는 확인되나 독립적 심층 분석 자료가 제한적 (검색 경유 🟡 출처에 의존) |
| **C** | 기본 재무 데이터만 확인 가능. 비상장·소규모·XBRL 미제출(외국 발행사 20-F 등) |

> ⚠️ 기준을 이 스킬이 **실제로 접근 가능한 출처**로 정의한 것이다. "실적 발표 녹취(transcript)"는
> A 기준에서 뺐다 — 트랜스크립트 제공처(Seeking Alpha 등)가 직접 접근 차단이라 검색 경유
> 🟡 상한이고, 그걸 A의 필수 조건으로 두면 **어떤 종목도 A를 받을 수 없다**.
>
> **B가 정상 기본값이다.** A는 10-K 원문 확인까지 요구하므로 조사 상한(WebFetch 8회) 안에서
> 8종목 전부에 주기는 어렵다. 전 종목이 A로 표기된 보고서는 등급 인플레를 의심한다.

> ⚠️ **등급이 낮다고 추천도를 깎지 않는다** — 자료가 적은 것과 기업이 나쁜 것은 다르다.
> 소형주는 구조적으로 자료가 적으므로, 등급을 추천도에 반영하면 2.5 편향 표의 '대형주 선호'가
> 뒷문으로 다시 들어온다.

### 🔴 대상 선정과 상한 (팬아웃 제어)

1. **2.3 병목 섹터의 Tier 1·2 기업을 먼저** 넣는다.
2. 남는 자리에 다른 섹터의 Tier 1 대표 1개씩.
3. **전체 상한 8종목.** 섹터가 6개라고 6×3=18종목을 분석하지 않는다.
4. 나머지 Tier 1·2와 Tier 3/4는 **4.9 간략 코멘트**에 1~2줄씩 몰아 쓴다.
5. 상한 때문에 뺀 종목이 있으면 **그 사실과 종목명을 4.9에 명시**한다(조용한 누락 금지).

6. 이 목록으로 **먼저 4.0-a 정량표를 채운다.** 정량표를 보고 후보를 교체해도 된다(예: 병목 섹터
   선두인데 ROIC가 섹터 최하위면 그 이유를 프로파일에서 다뤄야 하니 남기고, 단순 중복이면 교체).
   교체했으면 그 사실을 4.9에 남긴다.

> ⚠️ 이 단계는 종목당 Agent를 띄우지 않는다. 4.0-a를 채우는 조사 1회 + 프로파일 작성으로 끝낸다.
> 🔴 Agent를 쓴다면 하위 Agent 스폰 금지(TB-1), 재시도 1회(TB-2).

### 4.0 통합 비교표 — **2패스로 채운다** (필수 · 이 단계의 핵심 산출물)

종목을 하나씩 서술하면 각각은 그럴듯한데 서로 비교가 안 된다. 횡단 비교표가 있어야 "이 중
무엇이 나은가"에 답할 수 있다. 단 **정량 값과 판정 값은 같은 시점에 채울 수 없다.**

> 🔴 **순서를 반드시 지킨다.** 판정 열을 프로파일 전에 채우면 ★를 감으로 먼저 매기고 A~F에서
> 그 ★를 정당화하는 **역방향 논증**이 된다 (CLAUDE.md: 데이터 → 논리 → 결론).

#### 4.0-a 정량 비교표 (프로파일 **전**에 작성)

조회로 확보되는 값만 채운다. 판단이 들어가는 열은 아직 만들지 않는다.

| 티커 | 가치사슬 위치 | 시총 | PER | PBR | EV/EBITDA | ROIC | Gross Margin | FCF 마진 | 순부채/EBITDA |
|-----|------------|-----|-----|-----|-----------|------|--------------|---------|--------------|
| | | | | | | | | | |

- 값을 못 구하면 `⬛` 로 남긴다. **추정으로 채우지 않는다.**
- **동일 기준으로 채운다** — 한 종목만 forward PER, 나머지는 trailing PER이면 표가 거짓말을 한다.
  기준을 표 아래에 한 줄로 명시한다(예: "PER은 전부 TTM 기준, 2026-08-06").
- 이 표를 먼저 보면 **어느 종목을 깊이 볼지**가 드러난다 — 프로파일 대상 선정의 근거로 쓴다.
- **PBR 열은 6.2 산업 밸류에이션의 입력이다** — 비우면 6.2를 채울 근거가 없어진다.
  PER과 같은 페이지(`stockanalysis.com/stocks/{ticker}/statistics`)에 있으므로 추가 조회가 없다.
- 🔴 **수집 경로는 ⓪-2를 따른다** — FCF 마진·순부채·Gross Margin은 `_data.md`(SEC XBRL)에서,
  PER·PBR·EV/EBITDA·ROIC만 stockanalysis에서 보충한다.
  **2.2에서 이미 뽑은 ROIC는 그대로 옮겨 쓰고 재조회하지 않는다.**

#### 4.0-b 판정 요약표 (모든 프로파일 **후**에 되돌아와 작성)

A~F를 다 쓴 뒤 각 종목의 결론만 한 줄로 모은다. **여기 있는 값은 전부 위 프로파일에 근거가 있어야
하며, 새로 발명하지 않는다.**

| 티커 | 해자 종합 (B) | 안전마진 (E) | 하방 리스크 (F) | 추천도 (판정) | 정보충분도 | 퍼널 진출 |
|-----|-------------|------------|---------------|-------------|----------|---------|
| | ★N | N% 또는 산정 불가 | 상/중/하 | ★N | A/B/C | 예/아니오 |

- **4.0-a와 4.0-b의 종목 순서·개수를 같게 유지한다.** 4.0-b에만 있는 종목은 프로파일 없이
  판정한 것이므로 오류다.
- 이 표의 "해자 종합" 열이 8단계 "가장 넓은 해자" 행의 입력이다.
- **"퍼널 진출" 열은 `/industry-funnel` 2단계의 진입 우선순위로 인수된다**
  ([industry-funnel.md](skills/industry-funnel.md) ⓪-2). 따라서 '아니오'는 **탈락 선고가 아니라
  후순위 표시**다 — research는 프로파일 깊이로 보고 funnel은 5지표 정량으로 보므로 판정 축이 다르다.
  '아니오'라고 쓸 때는 그 종목을 왜 뒤로 미루는지 한 줄 이유를 함께 남긴다.

**종목 1개당 이 블록 하나**를 쓴다. `4.1 SCCO`, `4.2 TECK`… 처럼 **번호는 종목에 붙고**, 아래

> 후에 채우게 한 이유가 무력해진다. 제목의 `{한 줄 평}`은 판정이 아니라 **사업 요약**이다

#### F. 종목 수준 하방 리스크 (리루 / Li Lu)

6단계는 **산업**의 문명 트렌드를 보고, 여기서는 그 트렌드가 맞더라도 **이 종목**이 살아남는지를 본다
(트렌드 적중과 종목 생존은 다른 문제다 — 인터넷은 이겼지만 Cisco 주주는 20년 못 회복했다).

- 이 종목을 산 뒤 **-50%가 되면 추가 매수할 확신이 있는가?** 없다면 지금도 사지 않는다
- 그 하락이 **일시적 가격 변동인지, 영구적 자본 손실인지** 구분하는 관측 지표는 무엇인가
- 산업 트렌드가 예상대로 실현되는데도 **이 기업만 탈락하는 경로**는 무엇인가
  (가치 이전: 마진이 고객사·경쟁사·부품업체로 넘어가는 경우 / 승자독식에서 2등이 되는 경우)

**핵심 질문**: 주가 화면을 5년간 보지 못한다면, 그래도 이 종목을 보유하겠는가?

**하방 리스크 등급** (4.0-b 판정표에 옮길 값):

| 등급 | 기준 |
|-----|-----|
| **하** | -50%가 와도 추가 매수할 근거가 명확하다 (영구 손실 경로가 좁다) |

| **상** | -50%면 논제가 깨진 것이므로 추가 매수하지 않는다 |

#### 판정 (A~F 종합 — 개별 거장 아님)

**확률·영향도 척도 (고정 — 7.1이 이 값으로 분기한다)**

| 열 | 값 | 기준 |
|---|---|---|
| 확률 | **높음** / 보통 / 낮음 | 높음 = 향후 3년 내 발생을 시사하는 **관측된 사건**이 이미 있다 · 보통 = 구조적으로 가능하나 관측 없음 · 낮음 = 특정 조건이 겹쳐야 함 |
| 영향도 | **큼** / 보통 / 작음 | 큼 = 논제가 깨져 **영구 자본 손실** 경로가 열린다 · 보통 = 수익률이 깎이나 논제는 유지 · 작음 = 일시적 가격 변동 |

> 🔴 척도를 임의로 바꾸지 않는다 — 7.1의 "확률 높음 × 영향도 큼이 2개 이상 → 밴드 하한" 규칙이
> 이 표기에 의존한다. 상/중/하 같은 다른 표기를 쓰면 그 규칙이 적용되지 않고 상한이 감으로 정해진다.

### 5.2 역사적 유추
역사적으로 유사한 가치사슬 투자 테마를 찾고 최종 결과를 분석한다:
- 유추 산업은 무엇인가?
- 최종 승자는 누구였는가? (업스트림/미드스트림/다운스트림?)
- 대다수 투자자는 수익을 냈는가 손실을 봤는가?
- 현재 산업에 대한 시사점은 무엇인가?

예시 유추:
- 인터넷 버블(1995-2001): 인프라(Cisco) vs. 서비스(Amazon) 생존 구조
- 셰일 혁명(2010s): 서비스 기업(HAL/SLB) vs. E&P 기업 수익률 비교
- 스마트폰 생태계(2007-2020): 부품 공급업체 vs. OS/앱 플랫폼 승자 구조

### 5.3 편향 자기 점검
- **내러티브 편향**: 스토리가 너무 완벽하지 않은가?
- **앵커링 효과**: 최근 주가 상승에 앵커링되어 있지는 않은가?
- **군중 심리**: "모두가 사고 있기 때문에" 관심을 갖는 것은 아닌가?

## 6단계: 문명 트렌드 판단 (리루/Li Lu 프레임워크)

- 이 산업이 기반한 근본 트렌드는 "문명 수준의 패러다임 전환"인가, 아니면 "단계적 열풍"인가?
- 역사적으로 가장 유사한 기술 혁명의 유추는 무엇인가?
- 10-20년 후 이 산업의 최종 상태(endgame)는 무엇인가?
- 가치사슬에서 어떤 섹터가 "승자독식(winner-take-all)"을 실현할 가능성이 가장 높은가?
- 어떤 섹터가 파괴(disruption)될 가능성이 가장 높은가?

판정 기준을 잡기 위한 참고 예시:

| 산업 | 트렌드 판단 | 리루 관점 핵심 |
|-----|-----------|-------------|
| AI 인프라 | 패러다임 전환 가능성 높음 | 전기화/인터넷에 비견. 다만 가치사슬 중 어디가 남을지가 핵심 |
| 전기차/배터리 | 패러다임 전환 진행 중 | 내연기관 교체는 확실. 브랜드 승자는 불확실 |
| 헬스케어 AI | 구조적 성장, 아직 패러다임 전환 미확인 | 규제·수가 리스크가 핵심 변수 |
| 핀테크 | 성숙기 진입, 일부 과열 | 결제 네트워크(Visa/MA) 해자가 생각보다 강고 |

### 6.1 트렌드 판정 ⚑

위 질문들을 **하나의 판정으로 수렴**시킨다. 이 판정이 7.1 테마 비중 상한의 입력이다.

| 항목 | 기록 |
|------|------|
| **판정** | 패러다임 전환 / 진행 중 / 단계적 열풍 |
| 근거가 되는 역사적 유추 | (5.2와 같은 사례여도 무방 — 다르면 왜 다른지) |
| 10~20년 후 최종 상태 | |
| 이 판정을 뒤집을 관측 | |

> ⚑ **판정 근거는 미래 추정이므로 대부분 🔴[추정]이다.** "패러다임 전환"이라는 판정 자체에
> 신뢰도 등급을 달고, 기관 전망 간 편차가 크면 그 편차를 함께 적는다.
>
> ⛔ 판정이 **"단계적 열풍"인데 7단계에서 코어 포지션을 제안하지 않는다.** 열풍은 사이클
> 고점에서 코어로 들어가면 5.2 역사적 유추의 실패 사례를 그대로 반복한다.

### 6.2 산업 전체 밸류에이션 위치 ⚑

4단계 E는 **종목** 밸류에이션이다. 산업 전체가 비싼지는 별개 질문이고, 이게 없으면
5.1 "밸류에이션 거품 붕괴" 행과 8단계 "전체 밸류에이션 수준" 행을 채울 근거가 없다.

| 항목 | 기록 | 출처 |
|------|------|------|
| **선정 8종목 PER / PBR 중위값** | | 4.0-a 정량표 (표본 티커를 나열한다) |
| 산업 전체 PER / PBR | | 섹터 ETF 팩트시트의 포트폴리오 지표 (없으면 `⬛`) |
| **역사적 백분위** | 최근 10년 중 상위 N% 수준 | stockanalysis.com 개별 종목 PER 추이 · 섹터 ETF |
| 자금 흐름 | 섹터 ETF 순유입/유출, 기관 포지션 변화 | ETF 발행사 공시 · SEC 13F |
| 사이클 위치 | 초기 / 확장 / 성숙 / 쇠퇴 | 위 4개 + 5.2 역사적 유추 |

- 🔴 **4.0-a 중위값을 "산업 평균"이라고 부르지 않는다.** 4.0-a는 병목 섹터 선두를 우선 담은
  **의도적 편향 표본 8개**이고, 그 편향은 4단계의 설계 목적이다. 산업 전체 수치가 필요하면
  섹터 ETF에서 받는다 — 두 값이 크게 벌어지면 그 자체가 "병목 계층이 프리미엄을 받고 있다"는
  신호이므로 **둘을 나란히 적는다.**
- 백분위를 구할 수 없으면 `⬛`로 두고 **부록 A 1순위**에 올린다 — 이 값은 7.1 상한을 바꿀 수 있다.
- ⚠️ **6.1 판정과 6.2는 충돌할 수 있고, 그게 정상이다.** "패러다임 전환 + 역사적 고점 밸류에이션"은
  모순이 아니라 **가장 흔한 함정**이다(5.2 인터넷 버블이 정확히 그 조합이었다). 충돌하면 숨기지
  말고 7.1에서 밴드 하한을 택하는 근거로 쓴다.

## 7단계: 포트폴리오 배분 제안

> 🔗 **역할 경계** — 이 스킬은 **"가치사슬의 어느 계층에 얼마"** 까지가 결론이다. 개별 종목의

### 7.1 테마 비중 상한 결정 (1.4 × 6.1 판정의 함수) — **배분보다 먼저**

> 🔴 **상한을 먼저 정한다.** 7.2 배분표의 % 는 이 상한을 분모로 쓴다. 순서를 뒤집으면 분모를
> 모르는 상태에서 분자를 쓰게 되고, 상한이 "관찰만"으로 나왔을 때 이미 쓴 추천표를 지워야 한다.

상한은 감이 아니라 **앞선 두 판정의 조합**에서 나온다. 두 판정을 이 표에 대입해 밴드를 정하고,
그 밴드 안에서 산업 리스크(5.1)와 밸류에이션 위치(6.2)를 반영해 최종 % 를 제시한다.

| ↓1.4 체인 확신도 \ →6.1 트렌드 | 패러다임 전환 | 진행 중 | 단계적 열풍 |
|---|---|---|---|
| **높음** | 15~25% | 10~15% | 5~10% |
| **보통** | 10~15% | 5~10% | 3~5% |
| **낮음** | 5% 이하 | 3% 이하 | **관찰만 (0%)** |

밴드 안에서 최종값을 정하는 규칙:

| 조건 | 조정 |
|------|------|
| 6.2 밸류에이션 역사적 상위 20% 이내 | 밴드 **하한** 채택 |
| 6.2 백분위 `⬛`(산정 불가) | 밴드 하한 채택 (모르면 보수적으로) |
| 5.1에 확률 높음 × 영향도 큼이 2개 이상 | 밴드 하한 채택 |
| 위 어느 것도 아님 | 밴드 중간값 |

- 밴드를 벗어난 % 를 제시하려면 **그 이유를 명시**한다. 근거 없이 벗어나면 앞의 판정들이 장식이 된다.
- 위 % 는 **총 포트폴리오 대비 해당 테마의 상한**이다. 7.2의 코어/위성/옵션 비중은 이 상한을
  100%로 놓고 배분한 값이다 — 두 단위를 섞지 않는다.
- ⛔ **"관찰만(0%)"이 나오면 7.2를 종목 추천표로 쓰지 않는다** — 관찰 목록으로 낸다.

### 7.2 추천 포트폴리오 (7.1 상한을 100%로 놓고 배분)

| 레이어 | 비중 | 종목 (티커) | 소속 섹터 | 핵심 논리 |
|------|-----|-----------|---------|---------|
| **코어 포지션** | 테마 비중의 50-60% | | | 가장 확실하고 해자가 넓음 |
| **위성 포지션** | 테마 비중의 25-35% | | | 탄성이 크고 확실성이 약간 낮음 |
| **옵션 포지션** | 테마 비중의 5-15% | | | 고위험 고수익, 전액 손실 가능 |
| **ETF 대안** | 위 전체를 대체 가능 | | | 종목 선정이 어려울 때 "게으른 대안" |

- 종목은 **4.0-b 판정표에서만 가져온다.** 프로파일을 쓰지 않은 종목을 여기 올리지 않는다.
- 표 아래에 **환산값을 한 줄 적는다** — 예: "테마 상한 10% 기준 → 코어 5~6%, 위성 2.5~3.5%,
  옵션 0.5~1.5% (총 포트폴리오 대비)". 두 단위를 오해하지 않게 하는 장치다.
- 6.1이 "단계적 열풍"이면 코어 행은 비워두거나 ETF로 채운다(6.1 ⛔ 규칙).

   상한 밖 종목은 4.9 표에 1~2줄씩 남긴다. **상한 때문에 뺀 종목명을 반드시 명시**한다
   (조용한 누락은 "전부 검토했다"로 읽힌다)
5. **4.0-a 정량표와 4.0-b 판정표 둘 다 필수**다. 종목별 서술만 있고 횡단 비교표가 없으면
   미완성으로 본다. **4.0-a는 프로파일 전, 4.0-b는 프로파일 후**에 작성한다(순서 위반 시 역방향 논증)
6. NYSE/NASDAQ 전체 스캔은 가능한 한 완전하게 수행한다 — **SEC EDGAR SIC 스캔(10-K + 20-F) 포함**
7. 최종 보고서는 `reports/{섹터명}-industry-{YYYYMMDD}.md` 형식으로 저장한다.
   여기서 `{섹터명}`은 **아래 요건 13의 섹터 마커 값과 문자 단위로 동일**해야 한다
   (하이픈 포함 여러 단어여도 그대로 — `Fintech-Payments`, `GLP-1-Obesity`)
8. 결론은 명확하게, 구체적인 계층·비중 제안을 포함한다 (개별 종목 매수가는 후속 스킬 담당)
9. **판정 노드의 단방향 흐름을 지킨다** — 아래 순서를 거스르면 결론을 먼저 쓰고 근거를 맞추는
   역방향 논증이 된다:

   ```
   1.2/1.3 검증 → 1.4 체인 판정 ───────────────────────┐
   2.2 ROIC → 2.3 병목 판정 ──────────────────────────┤
        ↑                                             │
        └── (역검증 back-edge) ── 4.0-a·4.N 이 2.3 을 반증하면 2.3 을 수정한다
                                                       │
   3단계 스캔 → ⓪-2 도구 → 4.0-a 정량표 → 4.N 프로파일 → 4.0-b 판정표
                                                       │
   5.1 리스크 · 6.1 트렌드 · 6.2 밸류에이션 위치 ──────┴→ 7.1 상한 → 7.2 배분 → 7.3 신호 → 8단계 집계
   ```

   **유일하게 허용되는 역방향은 위 back-edge 하나뿐이다** — 4단계가 2.3을 반증했을 때 2.3을
   고치는 것. 이건 역방향 논증이 아니라 4단계의 설계 목적(병목 판정 역검증)이다. 그 외의
   역방향(예: 7.2 배분을 먼저 정하고 4.0-b를 맞추는 것)은 전부 금지다.
10. 각 분석 차원(A~F) 말미에 해당 거장의 "핵심 질문"을 배치한다
11. 모든 시가총액은 USD 기준 (B=billion, T=trillion)
12. **데이터 기준일 표기**: TAM, 가치사슬 구도, 점유율 등 핵심 수치마다 "(YYYY-MM 기준)" 형태로 데이터 기준일을 표기한다. 보고서 맨 위에 "데이터 기준일: YYYY-MM-DD"를 종합 표기한다. 후속 스킬(`/industry-funnel` 등)이 이 보고서를 입력으로 사용할 때 데이터 신선도를 판단하는 근거가 된다
13. **섹터 마커 (필수 · 대시보드 파싱 계약)**: H1 제목 **바로 다음 줄**에 남긴다.

    ```markdown
    # {산업명} 산업 리서치 — 가치사슬 전체 스캔
    <!-- funnel sector: Defense | finalists: NOC, GD, PLTR -->
    ```

    - `sector` 값은 **파일명에서 `-industry-{YYYYMMDD}.md` 를 떼어낸 문자열 전체**다.
      하이픈이 여러 개 있어도 앞토막만 쓰지 않는다:

      | 파일명 | `sector` 값 |
      |-------|-----------|
      | `Copper-industry-20260804.md` | `Copper` |
      | `Fintech-Payments-industry-20260729.md` | `Fintech-Payments` |
      | `GLP-1-Obesity-industry-20260723.md` | `GLP-1-Obesity` |

      같은 섹터의 퍼널 보고서(`{섹터명}-funnel-*.md`)와도 **표기가 완전히 같아야** 한다.
      표기가 갈리면 대시보드에서 섹터가 둘로 나뉘고, 섹터 자동 배정이
      "섹터 충돌" 경고를 낸다.
    - `finalists` 는 **7.2 추천 포트폴리오의 코어·위성·옵션 티커**만 쉼표로 나열한다(ETF·현금 제외).
    - 🔴 **`finalists` 를 비워두지 않는다.** 7.1이 "관찰만(0%)"으로 나오거나 6.1이 "단계적 열풍"이어서
      코어를 ETF로 채운 경우 7.2에 개별 티커가 없을 수 있다. 그때는 **4.0-b 판정표에서 추천도
      ★3(관찰 목록) 이상인 티커를 나열한다** — 비중 0%여도 그 종목은 이 섹터에 속하고, 대시보드의
      섹터 배정은 "지금 사는가"가 아니라 "무엇에 관한 보고서인가"를 나타낸다.
      비면 대시보드가 티커를 못 읽어 **섹터 자동 배정이 실패한다**
      (industry 보고서는 루트에 있어 `meta sector` 대체 경로가 없다).
    - 이 마커가 '티커 → 섹터' 자동 배정의 근거다(대시보드 `lib/sector-auto-map.ts`). 없으면 후속
      `/investment-team` 보고서를 써도 그 종목이 대시보드에서 '미분류'로 남는다.
    - ⚠️ 같은 섹터의 퍼널 보고서가 이미 마커를 남겼어도 **여기서도 남긴다** — 퍼널을 돌리지 않고
      이 스킬만 실행하는 경우가 있다(실측: `-industry-` 보고서 11건 전부 마커 누락 상태였다).

14. **부록 A — 데이터 부족 항목 (필수)**: ⬛로 남긴 공백을 나열만 하지 않고 **투자 판단에 미치는
    영향 순으로 정렬**한다.

    | 순위 | 기준 |
    |-----|-----|
    | 🔴 1순위 | 이 값이 채워지면 **결론이 바뀔 수 있는** 공백 |
    | 🟡 2순위 | 종목 판단을 보완하는 공백 (결론은 유지) |
    | ⬛ 3순위 | 미조사 영역 (조사 범위 밖이었음을 기록) |

    3단계 SIC 스캔에서 20-F 미조회 등으로 남은 **잔여 누락 가능성도 여기에 적는다**.

## 데이터 샘플 검사 (출고 절차)

보고서 작성 후, 데이터 샘플 검사를 실행하고 통과 시에만 발행한다:

```bash
# Step 1 — 샘플 검사 목록 추출 (15% 무작위 샘플링, 최대 12건)
python3 tools/report_audit.py extract \
  --report <보고서 파일 경로> --max 12

# Step 2 — 목록의 각 항목을 신뢰할 수 있는 출처에서 데이터 확인 (skills/financial-data.md 참고)

# Step 3 — 통과/반려 판정 출력
python3 tools/report_audit.py verdict \
  --results '<작성된 JSON>' \
  --report <보고서 파일명>
```

**[통과]** 전부 통과 → 보고서 발행 가능; **[반려]** 불통과 항목 있음 → 수정 후 재심사.

> ⚠️ `--max` 를 생략하면 기본 30건이고, 검사 1건 = 웹 왕복 1회다. 이 스킬은 최대 6개 Agent를
> 띄우는 팬아웃 스킬이므로 **12건으로 묶는다**([token-budget.md](skills/token-budget.md) TB-3,
> `/investment-team` 과 동일 기준). 12건으로 부족하다고 판단되면 올리되 그 이유를 보고서에 적는다.

## 데이터 신뢰도 표기 (필수)

본 보고서는 **[data-confidence.md](skills/data-confidence.md) 표준**을 적용한다:

- 핵심 수치·판단 옆에 **신뢰도 등급 + 유형 태그**를 단다 — 🟢높음(2+독립출처 교차검증 또는 SEC 원문 직접 확인) / 🟡보통(단일출처·경미편차·해석여지) / 🔴낮음(추정·미확정주장·구데이터) / ⬛데이터부족(공백 유지) + `[사실]`/`[추정]`/`[주장]`/`[의견]`. 산업 TAM·성장률·상업화 시점 등 미래 추정은 대부분 🔴[추정]이며 기관 간 편차를 함께 표기한다.
- **출처 독립성 주의**: 회사 IR·보도자료와 집계 사이트는 둘 다 회사 공시 파생이라 상호 독립이 아니다 → 🟢은 원문 직접 확인 또는 계보가 다른 두 출처를 요구한다.
- 보고서 **말미에 기계 판독용 신뢰도 요약 블록**을 포함한다(대시보드가 파싱):

      <!-- confidence-summary
      high: N
      medium: N
      low: N
      gap: N
      verdict: 높음|보통|낮음
      -->

  (아래에 사람용 요약 몇 줄: 등급별 개수 + 종합 판단 근거)
- ⚠️ verdict는 **"데이터 신뢰도"이며 "투자 매력도"가 아니다.** 두 축은 독립이며 자주 어긋난다. `[의견]` 태그는 verdict 계산 분모에서 제외한다.
