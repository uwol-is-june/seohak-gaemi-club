## 기록 규칙 (프로세스)

**1. 논제 수립 시 — 기본값은 항상 `관망`**

`/thesis-tracker`가 논제를 수립하거나 검토하면 콜 원장에 자동 기록된다.
사용자가 매수를 확인하지 않은 종목은 **예외 없이 `hold`(관망)** 으로 기록하고
'관찰 논제' 표에 넣는다. 모델이 보유 여부를 추측하지 않는다.

**2. 콜 종류 매핑 — `keep`과 `hold`를 절대 섞지 않는다**

| 상황 | call | 의미 | 적중 조건 |
|------|:----:|------|----------|
| 미보유, 진입가 대기 | `hold` | 관망 | 진입 밴드로 **내려오면** 적중 |
| 보유 중, 계속 보유 | `keep` | 보유 유지 | 하락하지 않으면 적중 |
| 신규/추가 매수 실행 | `buy` | 매수 | 상승 방향 적중 |
| 감량·전량 매도·회피 | `avoid` | 회피 | 하락 방향 적중 |

두 콜은 **정반대를 예측**한다. 실제 보유 여부만으로 판단한다.

**3. 사용자가 매수를 알리면 — 관망 콜을 덮지 않고 새 콜을 추가한다**

`"GOOGL 매수 $250에 3주"` 같은 입력이 오면:

1. 매수가·수량·날짜를 **사용자 입력 그대로** 기록 (모델이 가격을 추정하지 않는다)
2. 원장에 **`buy` 콜을 append** — 기존 `hold` 콜은 **수정·삭제하지 않는다**
   (관망 판단이 옳았는지도 채점 대상이다. 이력을 지우면 트랙레코드의 의미가 없다)
3. 이 파일에서 해당 행을 '관찰 논제' → '현재 보유 포지션'으로 이동
4. '매매 로그'에 매수 1행 추가
5. 논제 파일(`{티커}-thesis.md`)의 `보유 상태`·앵커가를 실제 매수가 기준으로 갱신하고
   추적 기록 테이블에 전환 사유를 남긴다

**4. 원장 직접 기록 (수동 필요 시)**

```bash
python3 tools/record_call.py \
  --ticker GOOGL --skill thesis-tracker \
  --report reports/GOOGL/GOOGL-thesis.md \
  --call hold \
  --target-low 232 --target-high 255 --horizon-months 12 \
  --load-bearing "핵심 가정들" --invalidation "레드라인들"
```

`priceAtCall`은 도구가 Yahoo에서 실측해 박제한다 — **모델 기억값 금지**.
